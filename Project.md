# Project Documentation: AI-Generated Text Detection Using Transformers 
 
## Project Overview 
 
### Purpose 
The primary purpose of this project is to develop a robust system for detecting whether a given piece of text was generated by an AI (e.g., GPT-4, Claude) or written by a human. 
 
### Research Objective 
To evaluate and compare the effectiveness of traditional machine learning baselines (TF-IDF + Linear Models/Trees) against state-of-the-art Transformer-based models (RoBERTa, DeBERTa-v3), and finally combine them into a hybrid ensemble for maximum detection accuracy. 
 
### Architecture Overview 
The project follows a tiered architecture: 
1. Data Layer: Ingests raw text from multiple sources, cleans it, and merges it into a unified format. 
2. Feature Engineering Layer: Extracts both statistical handcrafted features and high-dimensional TF-IDF vectors. 
3. Model Layer: 
   - Baseline Tier: Linear SVM, Logistic Regression, Naive Bayes, Random Forest, and XGBoost. 
   - Transformer Tier: RoBERTa-base and DeBERTa-v3-base fine-tuned for sequence classification. 
4. Ensemble Layer: A meta-model that aggregates probabilities from all lower-tier models to make a final prediction.

### Current Implementation 
- Language: Python 3.12 
- Core Frameworks: PyTorch, Hugging Face Transformers, Scikit-Learn, XGBoost. 
- Data Handling: Pandas, NumPy. 
 
### Current Workflow 
1. Run preprocessing/preprocess.py to generate final_dataset.csv. 
2. Run models/baseline/train.py to train baseline models and generate TF-IDF features. 
3. Run train_roberta.py and train_deberta.py to fine-tune transformers. 
4. Run models/ensemble/generate_base_predictions.py to collect predictions for all models. 
5. Run models/ensemble/train.py to train the final ensemble. 
 
### Current Strengths 
- Hybrid Approach: Combines the strength of statistical features (baselines) with semantic understanding (transformers). 
- Diverse Model Set: Uses a wide range of models from simple NB to complex DeBERTa. 
- Clean Pipeline: Modular structure with separate directories for preprocessing, features, and models. 
 
### Current Weaknesses 
- Split Inconsistency: Feature engineering and Transformer training scripts use different data split ratios, which can lead to evaluation discrepancies. 
- VRAM Constraints: Very small batch sizes (8) for transformers due to 4GB VRAM, potentially slowing convergence and stability. 
- Memory Inefficiency: Reliance on Pandas read_csv for the entire dataset may cause RAM bottlenecks as data grows.

## Data Pipeline 
 
### Dataset Location 
Raw data is stored in Datasets/. The final processed dataset is located at datasets/merged/final_dataset.csv. 
 
### Columns 
- text: The document content (string). 
- label: Binary target (0: Human, 1: AI). 
- source: The original dataset the text came from. 
 
### Label Mapping 
- Human -
- AI-Generated (GPT, Claude, etc.) -
 
Handled by preprocessing/preprocess.py: 
- Null byte removal. 
- Normalization of newlines and tabs. 
- Filtering samples with fewer than 20 words. 
 
1. TF-IDF: N-grams (1, 2), Max Features 50,000. 
2. Transformer Tokenization: Max Length 512, truncation, padding. 
 
### Train/Validation/Test Split 
- Transformers: 70% Train / 15% Val / 15% Test. 
- Baselines/FE: 70% Train / 10% Val / 20% Test.

## Model Pipeline 
 
### Models Used 
- Logistic Regression, Multinomial NB, Linear SVM, Random Forest, XGBoost, RoBERTa-base, DeBERTa-v3-base, Ensemble Meta-model 
 
### Training Procedure 
- Baselines: Scikit-learn and XGBoost. 
- Transformers: Hugging Face Trainer with AdamW and fp16. 
 
### Inference Pipeline 
1. TF-IDF to Baselines. 
2. Tokenizer to Transformers. 
3. Probs to Ensemble. 
 
### Ensemble Strategy 
Meta-classifier trained on probabilities from all base models.
